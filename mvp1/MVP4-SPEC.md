## 1. GLOBAL DECISIONS (G-series; implementers must not re-open them)

- **G1 — Enablement actuation is `RolloutEngine._set_enablement(unit_name, enable: bool)`, the single new `run_actuate` call site; it takes NO slot.** A plain pass-through method beside `_stop_unit`/`_start_unit` (same shape: one `run_actuate` call, nothing else). It never reads or writes `self.current`/`self.rollouts`/`self.counter`, takes no lock, and holds no state — "slotless" is the *absence* of engine coupling, not a new mechanism. Module-level function rejected: the engine is where every actuation already lives, MVP2 §2.1's sentence "`run_actuate` is called only by `RolloutEngine` methods" stays true verbatim, and the handler already holds the engine reference. `ROLLOUT_CALLSITES` becomes `frozenset({'_stop_unit','_start_unit','_daemon_reload','_set_enablement'})` — growth by exactly one name, per the contract's acceptance row. All preflight lives *outside* the method (G3), in the route handler — `_set_enablement` is a gateway wrapper, not a policy point (run_actuate's own membership/retired check is the last-line backstop, as everywhere).
- **G2 — Verb sets stay separate; `run_actuate` becomes a per-verb shape table.** `ACTUATE_SYSTEMCTL_VERBS = {"stop","start","daemon-reload"}` is **unchanged** (frozen by MVP2 tests and by the rollout/switch shape story). New constant beside it: `ENABLEMENT_VERBS = {"enable","disable"}`, disjoint by test. `run_actuate` shape rule, restated as a table (one legal argv per verb):
  - `daemon-reload` → exactly `["systemctl","--user","daemon-reload"]` (len 3, no unit — the len-5 branch now **excludes** `daemon-reload`, closing recon finding 2; regression-pin it).
  - `stop|start|enable|disable` → exactly `["systemctl","--user",verb,"--",unit]`, len 5, `unit in units`, `units[unit].retired is False`.
  Implementation: the existing len-5 branch condition becomes `argv[2] in (ACTUATE_SYSTEMCTL_VERBS | ENABLEMENT_VERBS) and argv[2] != "daemon-reload"`; membership + retired checks are the existing lines, so the RETIRED backstop covers the new verbs **by construction** (verified: lines 2998–3001 are verb-agnostic). `--now` is structurally impossible: it would be a sixth argv element or displace `"--"` — the exact-length/exact-position rule already excludes it; **stated, not re-implemented.** Growing `ACTUATE_SYSTEMCTL_VERBS` instead was rejected: it would put enablement verbs inside the set the rollout/switch story quantifies over ("lifecycle verbs only"), forcing every F10-adjacent assertion to carve exceptions.
- **G3 — Enable-collision preflight: boot-claims only, rung-blind, defaults count, gates don't exempt claimants, self-port blocks; disable always passes.** `enablement_preflight(unit_name, enable, snapshot, units, self_port)` — pure, snapshot-in (supports G9(i): the caller supplies a locked snapshot; the function never touches the watcher). Rules, in order: (1) target retired → fail (`retired` check row, MVP2 wording) — for *both* directions (RETIRED renders no checkbox; the route is belt, this is braces, `run_actuate` is suspenders). (2) `enable == False` → ok, no further checks (contract: disabling removes a boot claim; it cannot create a race). (3) `enable == True` → collect claimants: every **other** snapshot row with `retired == False`, `enabled == True`, and `row['port'] == target_row['port']` — **rung is deliberately ignored** (this is a boot-time race; runtime state is irrelevant — code comment says so), **`port_source == 'default'` counts** (two units both defaulting :8080 really collide at boot; same rule, no special case), **a claimant's kernel gate does NOT exempt it** (decided: complementary-`ExecCondition` pairs are a hand-maintained pattern Roundhouse cannot prove safe; the interlock is deliberately conservative — the refusal names the claimant's gate so the operator understands, and hand `systemctl` remains available for the pattern; note the target's own gate never blocks *its* enable, per the contract). Additionally `target_row['port'] == self_port` → pseudo-claimant `roundhouse (self)` (a dogfooded Roundhouse is itself an enabled boot claimant on that port). Any claimant → fail. Corollary, stated: enabling an *already-enabled* unit that sits in a pre-existing hand-made double-enable also answers 422 naming the claimants — the interlock surfaces the existing race rather than rubber-stamping it; disable is the way out. Returns `{"ok": bool, "checks": [...], "port": int, "claimants": [{"unit","alias","port","rung","enabled":true,"gate":<gate|null>}...]}`; fail detail frozen: `port {p} is already a boot claim of: {unit} (enabled, {rung}[, kernel-gated])…` / self-port: `port {p} is roundhouse's own port`.
- **G4 — Route `POST /api/units/<name>/enablement`, body `{"enabled": true|false}` (JSON bool, strictly).** Success `200 {"unit","enabled","was","changed","strategy_note"}` — `was` = snapshot `enabled` at preflight, `changed = (was != enabled_after)`. **Idempotent toggles execute anyway** (systemctl enable is idempotent and self-healing for degenerate `UnitFileState`s; one code path, no skip branch) and answer 200 with `changed: false`. Errors: 400 `bad_json` / `bad_body` (`enabled must be true or false` — rejects strings, numbers, null, absent); 404 unknown unit; **422 `enable_collision`** `{"error","port","claimants","detail"}` (its own error code — the UI renders claimants specially, per the acceptance row); 422 `preflight_failed` with the retired check row (RETIRED target, either direction — consistent with the edit route's shape); 403/401 per E8; 405 on GET; 500 `enablement_error` with systemctl's stderr when `run_actuate` fails at execute (host malfunction, not client error). **No slot check anywhere** — the contract's both-directions row is satisfied by *absence of code*, and a test pins that `engine.current` is untouched. `FROZEN_POST_ROUTES` grows to 7 entries; `do_POST` gains the `endswith('/enablement')` branch; the structural guard's fragment set gains `'/enablement'`.
- **G5 — Immediate read-back + a new SSE event `'enablement'`.** Without it the row would lag ≤ 3 s *for other viewers* and **forever** for the toggling one — the tick only emits `rung` events on rung/badge change, and enablement changes neither. Handler sequence after a successful `_set_enablement`: run `run_ro(['systemctl','--user','show','-p','UnitFileState','--',unit])` (read verb, in `READONLY_SYSTEMCTL_VERBS`), parse `UnitFileState=`, apply via new `Watcher.apply_unit_file_state(unit_name, value)` under `watcher.lock`, then publish `event: enablement` with `{"unit","enabled","strategy_note","ts"}` (note computed server-side per G6 — the payload carries it because the UI stays dumb and no rung event will refresh the row). `apply_unit_file_state` sets **only** `_state[unit]['unit_file_state']` — it MUST NOT stamp `sensed_at` (that would launder a stale `ActiveState` sample as fresh past `_confirm_off`'s freshness gate; docstring says so). Read-back failure degrades gracefully: respond with the requested value, leave watcher state to the tick (documented; no retry loop). Riding the `rung` event was rejected as a lie (rung didn't change) with the wrong payload shape.
- **G6 — Drift notes are server-computed: snapshot rows gain `'strategy_note'`.** New pure function in Section B beside `classify_port_claims`:
  ```python
  def strategy_note(enabled, rung, retired):
      if retired: return None
      if enabled and rung in ('OFF', 'STANDBY', 'FAILED'): return "returns at boot"
      if not enabled and rung in ACTIVE_RUNGS: return "manual — will not survive reboot"
      return None
  ```
  Exactly the contract's two strings; no third wording invented. `enabled + FAILED` → `returns at boot` is decided true-and-sufficient: systemd *will* retry it at boot, the FAILED rung already carries the failure signal, and the note answers only "does boot bring it back?". `enabled + STANDBY` → `returns at boot` (pinned by the acceptance row; the gate note stays separate and unchanged). Called once per unit row in `Watcher.snapshot()`; the detail route inherits it via `**row` (line 2717) with zero code; `serve_deployments`' `load_strategy` dict gains `'strategy_note': row.get('strategy_note')`. `test_snapshot_shape`'s frozen key set gains the key (same-task rule as MVP3).
- **G7 — Checkbox in the unit row, all non-RETIRED sections, confirm-less, truth-showing when read-only.** A `<label class="enable-toggle">` with `<input type="checkbox">` + text `boot`, rendered in `renderUnitList` for categories `active|standby|off|failed` (never `retired`), right-aligned after `unit-row-left`. `checked = unit.enabled` — **always the real state**, including read-only mode where the input gets the `disabled` attribute (greyed): a checkbox showing the truth *is* the glanceable audit column; showing unchecked would falsify it. Click handling: `stopPropagation` (the row's onclick opens the detail pane), input disabled while the POST is in flight. **Confirm-less both directions** (decided: preflight blocks the only dangerous case, disable is safe by contract, and a checkbox behind a modal is miserable UX). On 200: update `unit.enabled` + `unit.strategy_note` from the body, re-render. On 422 `enable_collision`: revert the checkbox, toast naming the claimants. On 401: revert + `showTokenError()`. On 500: revert + toast with detail. Never render optimistic state — the checkbox reflects `state.units` only. Detail pane: a `Load strategy` row (`on-boot (enabled)` / `manual (disabled)`) plus the note line when non-null; **no second checkbox** (one control per unit; the pane is reached from the row). The drift note also renders in the row's `detailSpan` as `· <note>` — neutral color, no new red/amber sharers. 44 px: `.enable-toggle` joins the frozen selector rule with a 24 px input (same pattern as `.stop-tick-row`).
- **G8 — Dogfood: `roundhouse.service` is NOT a selected unit; its strategy is sensed cheaply and shown on the port board's self cell.** Selecting it (via `# roundhouse: manage`) was rejected: the llama pipeline would misrender it (LOADING forever, `no_ready_marker`), the edit/switch paths would accept a non-llama unit, and a checkbox that can disable Roundhouse's own boot-return from its own UI is a footgun with no acceptance row. ## 3. ENABLEMENT SPEC (exact)

**Gateway.** `_set_enablement(self, unit_name: str, enable: bool) -> None` → `run_actuate(["systemctl","--user","enable" if enable else "disable","--",unit_name], self.units)` — one line, default timeout (90 s; enablement is a symlink operation, no new constant). `run_actuate` accepts exactly the G2 table; rejects by shape: `--now` (len 6), unit lists (len > 5), missing `--`, `daemon-reload` with a unit; rejects by membership: non-selected, RETIRED.

**Preflight.** G3, verbatim. Called only from `handle_enablement` with `locked_snapshot(watcher)` — one snapshot per request, no torn reads (same doctrine as F4/§3.3).

**Handler `handle_enablement(unit_name)` — exact sequence:**
1. Parse body; `data.get('enabled')` must be `True` or `False` (`isinstance(v, bool)`) → else 400 `bad_body`.
2. `unit_name not in watcher.units` → 404.
3. `engine = self.server.rollout_engine`; absent → 500 `no_engine` (unreachable when unarmed — 403 fires first; same guard as the switch handlers).
4. `snap = locked_snapshot(watcher)`; `pf = enablement_preflight(unit_name, enabled, snap, watcher.units, self.server.port)`; not ok → 422 (`enable_collision` with claimants, or `preflight_failed` with the retired row).
5. `was` = target row's `enabled` from `snap`.
6. `engine._set_enablement(unit_name, enabled)`; `ActuationError` → 500 `enablement_error` (stderr in detail; e.g. a unit with no `[Install]` section surfaces here honestly — no special code).
7. Read-back per G5; `enabled_after` from it (or the requested value on read failure); apply under `watcher.lock`.
8. `note = strategy_note(enabled_after, snap-row rung, retired=False)`.
9. `event_bus.publish('enablement', {"unit": unit_name, "enabled": enabled_after, "strategy_note": note, "ts": time.time()})`.
10. 200 `{"unit","enabled": enabled_after,"was","changed": was != enabled_after,"strategy_note": note}`.

Zero file writes, zero git: the handler's only subprocess traffic is one `run_actuate` + one `run_ro` — proven three ways (§7.3).

| route | method | success | errors |
|---|---|---|---|
| `/api/units/<name>/enablement` | POST | 200 (body above) | 400 `bad_json`/`bad_body`; 404; 422 `enable_collision` \| `preflight_failed`(retired); 403/401 per E8; 405 GET; 500 `enablement_error` |

`FROZEN_POST_ROUTES = (…MVP3 six…, "/api/units/<name>/enablement")`. Status doctrine unchanged; no 409 exists for this route (slotless — decided, tested).

**SSE.** New event name `enablement`, payload `{"unit","enabled","strategy_note","ts"}`. Existing events untouched. The snapshot (initial SSE frame + `/api/units`) carries `enabled` + `strategy_note` per row, so refresh/reconnect agrees with the stream. ## 10. RISKS — top 3 mechanical-coder failure modes and the guards placed

1. **The reboot drill fails for environmental reasons and gets "fixed" in code** — the classic trap: without `loginctl enable-linger`, *no* user unit starts at container boot, and a coder facing "enabled unit didn't come back" may bolt reconciliation logic onto Roundhouse (violating the milestone's entire premise) instead of fixing the container. **Guards:** linger is an unconditional setup-script step with a comment naming this exact failure mode; the drill asserts llama-task (the pre-existing enabled canary) returned *before* judging any MVP4 behavior; the contract's "no autonomous action — ever" plus the AST guards leave no sanctioned place for reconciliation code to live.
2. **Lock unification over-applied → deadlock, or under-applied → the debt survives.** A coder "unifying" the engine's already-locked sites onto `locked_snapshot` deadlocks a worker thread on the non-reentrant lock while it holds the lock the tick and every GET need — freezing the whole process; or converts only some of the four sites. **Guards:** §6(i) enumerates exactly four edit sites and explicitly forbids touching in-`with` sites; `locked_snapshot`'s docstring states the never-under-the-lock rule; `test_snapshot_calls_locked` catches new unlocked sites; the route-test harness's socket timeouts turn a deadlock into a red test, not a hang.
3. **Scope creep on the toggle** — `--now`, a "helpful" daemon-reload after enabling, a slot check "for safety", or optimistic checkbox state in the UI. **Guards:** the G2 shape table makes `--now` unrepresentable; the route-leg zero-write test asserts the recorder saw *exactly* one enable/disable plus one show (any extra verb fails it); `TestEnablementSlotless` asserts `engine.current` identity across a toggle; the UI spec renders only from `state` updated by 200/SSE payloads, and the static tests pin the listener + stopPropagation so the row cannot silently diverge from systemd's truth.

**Out of scope (do not build, per contract):** autonomous reconciliation beyond systemd's own, any desired-state store, `--now` semantics, mask/unmask, system-level units, multi-host, openrc or any init abstraction (decided: never), template/instance units, migration steps for the live fleet (it already conforms), a checkbox for `roundhouse.service` itself (G8).
